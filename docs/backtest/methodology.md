# Backtest Methodology — Knowledge PTalk

> Source-of-truth for *how* we prove the RAG tutor works. Pairs with
> [`metric-definitions.md`](metric-definitions.md) (what each number means) and
> [`failure-taxonomy.md`](failure-taxonomy.md) (how we name what broke).
> Baseline of record: `reports/backtest/2026-06-17_full-sweep/` (see
> [`../project_state/2026-06-22-canonical.md`](../project_state/2026-06-22-canonical.md)).

## 0. What the backtest must prove

The north star is: *bám đúng bài/trang đang mở · giảng/đọc/luyện · sạch nguồn ·
độ trễ thấp · từ chối khi ngoài bài thay vì đoán.* The backtest exists to prove
**five claims**, each with a hard metric:

| # | Claim | Metric (see metric-definitions.md) | Gate |
|---|-------|-----------------------------------|------|
| 1 | **Bám đúng bài** (anchors the right lesson) | `anchor_at_1` (production/anchored path) | ≥ 97.0% |
| 2 | **Từ chối đúng** (refuses out-of-scope instead of guessing) | `guard_accuracy` = `refusal_recall`; `refusal_precision` | guard ≥ 98.1% |
| 3 | **Không leak nguồn** (clean source) | `source_cruft_real` | = 0 |
| 4 | **Không lỗi runtime** | `error_count` | = 0 / ~40k |
| 5 | **Độ trễ thấp** | `latency p50/p95/p99` | p95 (median book) ≤ 400 ms |

A change "passes the backtest" iff a fresh run clears all five and does not
regress any per-book slice beyond tolerance (see §4 regression gate).

## 1. How a case is built and scored (the existing engine)

The scorer is `rag_edu/scripts/schema_v3_2026_06/backtest_book.py` (unchanged by
this toolkit). Per book `(subject, grade, book_set, tap)`:

1. **Ground truth** is pulled from Neo4j (`bolt://localhost:7688`): every
   `:Lesson` with its `work_name`, `trang_from/to`, recite/practice availability,
   and one theory chunk.
2. **Questions** (~500/book) are generated by Gemma (:8080) in a *student voice*
   (short, diacritic-dropping, teen-speak) across **dimensions × intents** plus
   adversarial guards (~15%): `current_lesson`, `trang_query`, `trang_profile`,
   `name_query`, `content_only`, `practice`, `recite`, and `guard_*`
   (chitchat / offtopic / out-of-book / out-of-page / trap-word / trap-year).
3. **Run**: each `(query, user_profile)` is POSTed to `/retrieve` on the
   **canary** server (`:8889`/`:8890` — never prod `:8888`).
4. **Score** (the definitions this toolkit mirrors exactly):
   - `anchor` = `norm(work_name_returned) == norm(expected_work)` (diacritic-fold).
   - `mode` = anchor correct **and** returned `tier` == expected tier.
   - `guard` pass = returned `tier` **not** in `CARD_TIERS`
     (`lesson_card`/`lesson_practice`/`lesson_recite`).
   - `cruft` = source-leak keyword present in served context **and** a card was
     emitted (see the cruft correction in metric-definitions.md §cruft).
   - `latency` = wall-clock ms per `/retrieve` call → p50/p95/p99.

Output is one aggregate JSON per book (top-level metrics + `by_dimension` +
`sample_fails` + `latency_ms`).

> **`content_only` is refuse-by-design, not the gate.** When the client gives no
> anchor and the utterance never names the lesson, the correct behavior is often
> to refuse (don't guess). The canonical **anchor 97.0%** is the
> *production/anchored path* — it **excludes** `content_only`. Including it gives
> ~85% and understates production, where the client always sends `current_lesson`.
> This toolkit reports **both** and gates on the production-path figure.

## 2. The four test tiers

| Tier | What | Cost | Server? | Where |
|------|------|------|---------|-------|
| **1 · Unit** | Pure metric + taxonomy functions on tiny inline fixtures. Proves the *scoring* is correct (incl. the cruft real-vs-false-positive split). | ms | No | `packages/backtest/tests/test_metrics.py` |
| **2 · Golden routing** | A small, **version-controlled** set of hand-pinned cases (`schemas/backtest_case.v1.json`) replayed against `/retrieve`. Deterministic; pins specific routing behaviors and known-weak slices. | seconds | Canary | golden set (curated) + replay harness |
| **3 · Full sweep** | The Gemma-generated ~500/book × ~81 books ≈ 40k cases. Broad coverage; the source of the headline baseline. | ~hours, $ | Canary + Gemma + Neo4j | `scripts/run_full_sweep.sh` → `backtest_book.py` |
| **4 · Regression gate** | Diff a candidate run vs the baseline run; PASS/FAIL on absolute floors + per-book regression tolerances. No new data — pure diff of two report dirs. | ms | No | `packages/backtest/compare_runs.py` / `scripts/compare_backtest_runs.py` |

Tiers 1 and 4 are **free and offline** — run them on every change. Tiers 2 and 3
need a canary server and (for 3) Gemma; run them deliberately, never against prod.

## 3. Targeted vs full

- **Targeted** (default during iteration): score ONE weak book and diff it.
  ```bash
  RUN=1 PORT=8889 scripts/run_full_sweep.sh toan 4 CTST none
  python3 -m packages.backtest.reporters reports/backtest/<date>_full-sweep
  ```
  Use this to work a single slice (e.g. *Toán tiểu học 4–6 anchoring 82–86%*)
  without paying for the whole sweep.

- **Full** (before a promote/release): score the whole matrix on the candidate
  server, then regression-diff against the baseline.
  ```bash
  RUN=1 PORT=8890 scripts/run_full_sweep.sh --all          # candidate
  python3 scripts/compare_backtest_runs.py \
      reports/backtest/2026-06-17_full-sweep \
      reports/backtest/<date>_full-sweep
  ```
  The full sweep is expensive and must hit the **canary/candidate** port only.

## 4. The regression gate (Tier 4 detail)

`compare_runs.compare(before_dir, after_dir)` joins per-book on the `book` label
and FAILS the candidate if any of:

- global `anchor_at_1` < 97.0 or `guard_accuracy` < 98.1, or
- `source_cruft_real` > 0, or `error_count` > 0, or
- any single book drops anchor > 0.5 pp or guard > 0.5 pp vs baseline, or
- any single book's p95 rises > 50 ms vs baseline, or
- a baseline book is **missing** from the candidate run.

This is the safety net the canonical doc calls out: *"rủi ro lớn nhất là refactor
làm tụt anchor/guard mà không có backtest diff để bắt."* No merge without a fresh
report + a green diff.

## 5. Reproducing the baseline locally (no server)

The aggregate reports are enough to recompute the headline numbers offline:

```bash
python3 -m packages.backtest.reporters reports/backtest/2026-06-17_full-sweep
```
Expected (matches canonical): anchor@1 (production path) **97.5%**, guard
**98.1%**, `source_cruft_real` **0**, `source_cruft_test_false_positive` **204**,
errors **0**, gate **PASS**. The 204 is the historical false positive
(see metric-definitions.md), not real cruft.

## 6. Constraints (do not violate)

- Runtime is **not in this repo** — it is single-file `rag_server.py` on the
  server. This toolkit never imports or mutates it; it only consumes reports.
- **Never** point the sweep at prod `:8888` (the wrapper refuses, exit 3).
- The scorer (`backtest_book.py`) is the behavioral oracle; this toolkit mirrors
  its scoring *exactly* (`norm()`, `CARD_TIERS`) so offline metrics agree with it.
- The full sweep is expensive — prefer targeted runs while iterating.
